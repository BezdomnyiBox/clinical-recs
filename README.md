# Клинические рекомендации из научных статей

Путь данных: PDF → страницы → карточки доказательств → тезисы по разделам → редактор → экспорт по схеме.
Подробная структура и назначение файлов: `docs/STRUCTURE.md`.

## Запуск

    cp .env.example .env      # впишите OPENROUTER_API_KEY и смените пароли
    docker compose up --build

Интерфейс: http://localhost:5173, API и документация: http://localhost:8000/docs
База данных (Adminer): http://localhost:8080 - система MySQL, сервер `mysql`, пользователь, пароль и база из `.env`

API применяет ожидающие миграции Alembic перед запуском. Для ручного управления миграциями внутри контейнера:

    docker compose exec backend alembic current
    docker compose exec backend alembic history

Новая миграция после изменения моделей:

    docker compose exec backend alembic revision --autogenerate -m "описание изменения"

Проверьте сгенерированную ревизию и включите её в коммит. Для существующей базы начальная ревизия использует уже созданные таблицы, если в них присутствуют все ожидаемые колонки, и добавляет недостающие таблицы и индексы. Если в существующих таблицах не хватает колонок, запуск остановится без их удаления; сначала сделайте резервную копию и подготовьте ревизию для фактической схемы.

## Схема данных

`backend/app/spec/kr_recommendation.schema.json` - двухуровневая схема (доказательства -> тезисы). От выданной версии отличается:
в `evidence_unit` добавлены обязательные `quote`, `page`, `document_id`; в `study_design_enum` добавлены три дизайна из шкал 103н.
`GET /api/projects/{id}/export/json` отдаёт документ по схеме, `/export/validate` проверяет его, `/export/full` добавляет служебные данные.

## Проверка без обращения к LLM

    cd backend && python -m tests.test_extract_offline путь/к/статье.pdf

## Что сделано

Загрузка и дедупликация PDF, поиск/валидация по offline-срезу МКБ-10 v464, чек-лист соответствия требованиям с сохранением ответов, проверка релевантности, извлечение карточек с проверкой цитат и смысла,
предварительные тезисы по явным рекомендациям из статей, УДД/УУР, защита правок эксперта при повторной
обработке с показом ожидающей версии, экспорт JSON/текста/Word по шаблону КР 2026, метрики на эталоне и глоссарий.

## Что ещё не сделано

3. Метрики доступны через `/api/evaluation/metrics`; нужен размеченный эталонный набор
4. Эксперимент, отложенные документы и отчёт сдачи требуют `Статьи.zip` и списка участников
